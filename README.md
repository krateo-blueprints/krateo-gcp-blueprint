# Krateo GCP Blueprints

A catalog of [Krateo](https://krateo.io) blueprints that expose **Google Cloud resources** as
self-service Krateo Compositions, backed by
[Config Connector](https://cloud.google.com/config-connector/docs/overview).

Each blueprint is a Helm chart whose templates render a **native Config Connector custom
resource** (e.g. `storage.cnrm.cloud.google.com/v1beta1` `StorageBucket`). When you create a
Composition, Krateo renders the chart, the Config Connector resource lands in the cluster, and
the Config Connector controller provisions the real Google Cloud resource and reports status
back. A sibling `CompositionDefinition` registers each chart with Krateo.

Unlike the AWS catalog, **the operator ships here too** — see [`operator/`](operator/). Config
Connector is a dependency, and in Krateo every dependency is a blueprint.

## Layout

- `blueprints/<service>/<resource>/` — one Config Connector Kind each (**206 charts across 62
  services**). The Composition `spec` mirrors the Config Connector resource `spec`.
- `operator/` — Config Connector itself, as two compositions:
  - `krateo-gcp-configconnector-crds` — the `ConfigConnector` and `ConfigConnectorContext` CRDs
  - `krateo-gcp-configconnector` — the operator and the cluster-scoped `ConfigConnector` CR
- `tools/kccgen/` — the generator that produces every blueprint from an upstream CRD.

Only resources upstream marks **stable** are published. Config Connector's alpha tier is
deliberately excluded: those schemas change without notice, and a Composition CRD that changes
shape under a running install is a wedge, not an upgrade.

## Install

1. **Install Config Connector** — see [`docs/installing-controllers.md`](docs/installing-controllers.md).
2. **Configure Google Cloud credentials** — see [`docs/authentication.md`](docs/authentication.md).
3. **Krateo `core-provider`** installed in the cluster.

Every chart is published to GHCR:

```
oci://ghcr.io/krateo-blueprints/charts/gcp-<service>-<resource>:<version>
```

## Configure

A Composition's `spec` **mirrors the Config Connector resource `spec`**, plus a `projectId` field
that becomes the `cnrm.cloud.google.com/project-id` annotation. Leave `projectId` empty to
inherit the project from the namespace, or when the resource's own spec carries a `projectRef`.

Krateo's `core-provider` builds the Composition CRD from each chart's `values.schema.json`
**only** — it never reads `values.yaml` — so the schema is the contract driving both the CRD and
the portal form.

## Develop

Every blueprint under `blueprints/` is generated by [`tools/kccgen`](tools/kccgen) from the
upstream Config Connector CRD and validated with `helm template`:

```sh
go run ./tools/kccgen \
  -crd https://raw.githubusercontent.com/GoogleCloudPlatform/k8s-config-connector/master/config/crds/resources/apiextensions.k8s.io_v1_customresourcedefinition_storagebuckets.storage.cnrm.cloud.google.com.yaml \
  -out blueprints -lint
```

Pull requests run `.github/workflows/lint.yaml`, which renders every chart. Charts publish to
GHCR on a semver tag via `.github/workflows/release-tag.yaml`.
