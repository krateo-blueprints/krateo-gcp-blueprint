# Krateo Blueprint — Google Cloud Logging LoggingLogBucket

> Generated by `tools/kccgen` from the Config Connector `LoggingLogBucket` CRD (`logging.cnrm.cloud.google.com`).

Provisions a Google Cloud Logging **LoggingLogBucket** through
[Config Connector](https://cloud.google.com/config-connector/docs/overview). The chart renders a
native `logging.cnrm.cloud.google.com/v1beta1` `LoggingLogBucket` resource; the Config Connector controller
reconciles it into the real Google Cloud resource and reports status back.

Once the `CompositionDefinition` is applied, every `GcpLoggingLogbucket` Composition you create
becomes a Google Cloud LoggingLogBucket.

Upstream stability level of this resource: **stable**.

## Prerequisites

- **Config Connector installed** in the cluster — see
  [`../../../docs/installing-controllers.md`](../../../docs/installing-controllers.md).
- **Google Cloud credentials configured** — Workload Identity (recommended) or a service-account
  key, plus a `ConfigConnectorContext` in the target namespace. See
  [`../../../docs/authentication.md`](../../../docs/authentication.md).
- Krateo `core-provider` installed.

## Configuration

Composition `spec` fields **mirror the Config Connector LoggingLogBucket spec**. Full schema in
[`chart/values.schema.json`](chart/values.schema.json). The extra `projectId` field sets the
`cnrm.cloud.google.com/project-id` annotation; leave it empty to inherit the project from the
namespace, or when the spec already carries a `projectRef`.

## How to install

```sh
kubectl create namespace gcp-logging-system
kubectl apply -f compositiondefinition.yaml   # publishes the GcpLoggingLogbucket type
kubectl apply -f customform.yaml              # optional: portal card + form
```

This publishes a `GcpLoggingLogbucket` Composition type (`composition.krateo.io/v0-1-0`,
plural `gcplogginglogbuckets`), pulling the chart from
`oci://ghcr.io/krateo-blueprints/charts/gcp-logging-logbucket`.

### Create a Composition

```yaml
apiVersion: composition.krateo.io/v0-1-0
kind: GcpLoggingLogbucket
metadata:
  name: my-logbucket
  namespace: gcp-logging-system
spec:
  projectId: my-gcp-project
  # ... LoggingLogBucket spec fields (see values.schema.json)
```

### Check status

```sh
kubectl get gcplogginglogbuckets.composition.krateo.io -n gcp-logging-system
kubectl get logginglogbuckets.logging.cnrm.cloud.google.com -A
```
