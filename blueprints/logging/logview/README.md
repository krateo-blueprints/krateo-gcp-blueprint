# Krateo Blueprint — Google Cloud Logging LoggingLogView

> Generated by `tools/kccgen` from the Config Connector `LoggingLogView` CRD (`logging.cnrm.cloud.google.com`).

Provisions a Google Cloud Logging **LoggingLogView** through
[Config Connector](https://cloud.google.com/config-connector/docs/overview). The chart renders a
native `logging.cnrm.cloud.google.com/v1beta1` `LoggingLogView` resource; the Config Connector controller
reconciles it into the real Google Cloud resource and reports status back.

Once the `CompositionDefinition` is applied, every `GcpLoggingLogview` Composition you create
becomes a Google Cloud LoggingLogView.

Upstream stability level of this resource: **stable**.

## Prerequisites

- **Config Connector installed** in the cluster — see
  [`../../../docs/installing-controllers.md`](../../../docs/installing-controllers.md).
- **Google Cloud credentials configured** — Workload Identity (recommended) or a service-account
  key, plus a `ConfigConnectorContext` in the target namespace. See
  [`../../../docs/authentication.md`](../../../docs/authentication.md).
- Krateo `core-provider` installed.

## Configuration

Composition `spec` fields **mirror the Config Connector LoggingLogView spec**. Full schema in
[`chart/values.schema.json`](chart/values.schema.json). The extra `projectId` field sets the
`cnrm.cloud.google.com/project-id` annotation; leave it empty to inherit the project from the
namespace, or when the spec already carries a `projectRef`.

## How to install

```sh
kubectl create namespace gcp-logging-system
kubectl apply -f compositiondefinition.yaml   # publishes the GcpLoggingLogview type
kubectl apply -f customform.yaml              # optional: portal card + form
```

This publishes a `GcpLoggingLogview` Composition type (`composition.krateo.io/v0-1-0`,
plural `gcplogginglogviews`), pulling the chart from
`oci://ghcr.io/krateo-blueprints/charts/gcp-logging-logview`.

### Create a Composition

```yaml
apiVersion: composition.krateo.io/v0-1-0
kind: GcpLoggingLogview
metadata:
  name: my-logview
  namespace: gcp-logging-system
spec:
  projectId: my-gcp-project
  # ... LoggingLogView spec fields (see values.schema.json)
```

### Check status

```sh
kubectl get gcplogginglogviews.composition.krateo.io -n gcp-logging-system
kubectl get logginglogviews.logging.cnrm.cloud.google.com -A
```
