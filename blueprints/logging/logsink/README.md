# Krateo Blueprint — Google Cloud Logging LoggingLogSink

> Generated by `tools/kccgen` from the Config Connector `LoggingLogSink` CRD (`logging.cnrm.cloud.google.com`).

Provisions a Google Cloud Logging **LoggingLogSink** through
[Config Connector](https://cloud.google.com/config-connector/docs/overview). The chart renders a
native `logging.cnrm.cloud.google.com/v1beta1` `LoggingLogSink` resource; the Config Connector controller
reconciles it into the real Google Cloud resource and reports status back.

Once the `CompositionDefinition` is applied, every `GcpLoggingLogsink` Composition you create
becomes a Google Cloud LoggingLogSink.

Upstream stability level of this resource: **stable**.

## Prerequisites

- **Config Connector installed** in the cluster — see
  [`../../../docs/installing-controllers.md`](../../../docs/installing-controllers.md).
- **Google Cloud credentials configured** — Workload Identity (recommended) or a service-account
  key, plus a `ConfigConnectorContext` in the target namespace. See
  [`../../../docs/authentication.md`](../../../docs/authentication.md).
- Krateo `core-provider` installed.

## Configuration

Composition `spec` fields **mirror the Config Connector LoggingLogSink spec**. Full schema in
[`chart/values.schema.json`](chart/values.schema.json). The extra `projectId` field sets the
`cnrm.cloud.google.com/project-id` annotation; leave it empty to inherit the project from the
namespace, or when the spec already carries a `projectRef`.

## How to install

```sh
kubectl create namespace gcp-logging-system
kubectl apply -f compositiondefinition.yaml   # publishes the GcpLoggingLogsink type
kubectl apply -f customform.yaml              # optional: portal card + form
```

This publishes a `GcpLoggingLogsink` Composition type (`composition.krateo.io/v0-1-0`,
plural `gcplogginglogsinks`), pulling the chart from
`oci://ghcr.io/krateo-blueprints/charts/gcp-logging-logsink`.

### Create a Composition

```yaml
apiVersion: composition.krateo.io/v0-1-0
kind: GcpLoggingLogsink
metadata:
  name: my-logsink
  namespace: gcp-logging-system
spec:
  projectId: my-gcp-project
  # ... LoggingLogSink spec fields (see values.schema.json)
```

### Check status

```sh
kubectl get gcplogginglogsinks.composition.krateo.io -n gcp-logging-system
kubectl get logginglogsinks.logging.cnrm.cloud.google.com -A
```
