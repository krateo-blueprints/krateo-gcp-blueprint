# Krateo Blueprint — Google Cloud Storage StorageDefaultObjectAccessControl

> Generated by `tools/kccgen` from the Config Connector `StorageDefaultObjectAccessControl` CRD (`storage.cnrm.cloud.google.com`).

Provisions a Google Cloud Storage **StorageDefaultObjectAccessControl** through
[Config Connector](https://cloud.google.com/config-connector/docs/overview). The chart renders a
native `storage.cnrm.cloud.google.com/v1beta1` `StorageDefaultObjectAccessControl` resource; the Config Connector controller
reconciles it into the real Google Cloud resource and reports status back.

Once the `CompositionDefinition` is applied, every `GcpStorageDefaultobjectaccesscontrol` Composition you create
becomes a Google Cloud StorageDefaultObjectAccessControl.

Upstream stability level of this resource: **stable**.

## Prerequisites

- **Config Connector installed** in the cluster — see
  [`../../../docs/installing-controllers.md`](../../../docs/installing-controllers.md).
- **Google Cloud credentials configured** — Workload Identity (recommended) or a service-account
  key, plus a `ConfigConnectorContext` in the target namespace. See
  [`../../../docs/authentication.md`](../../../docs/authentication.md).
- Krateo `core-provider` installed.

## Configuration

Composition `spec` fields **mirror the Config Connector StorageDefaultObjectAccessControl spec**. Full schema in
[`chart/values.schema.json`](chart/values.schema.json). The extra `projectId` field sets the
`cnrm.cloud.google.com/project-id` annotation; leave it empty to inherit the project from the
namespace, or when the spec already carries a `projectRef`.

## How to install

Register it with the CompositionDefinition attached to a release of this repository, stamped
with that release's chart version. The `compositiondefinition.yaml` beside this README carries
the `CHART_VERSION` placeholder, which only the release replaces, so it is not meant to be applied.

```sh
VERSION=X.Y.Z   # a release of this repository: https://github.com/krateo-blueprints/krateo-gcp-blueprint/releases
kubectl create namespace gcp-storage-system
kubectl apply -f "https://github.com/krateo-blueprints/krateo-gcp-blueprint/releases/download/${VERSION}/compositiondefinition-gcp-storage-defaultobjectaccesscontrol.yaml"   # publishes the GcpStorageDefaultobjectaccesscontrol type
kubectl apply -f customform.yaml              # optional: portal card + form
```

This publishes a `GcpStorageDefaultobjectaccesscontrol` Composition type (`composition.krateo.io/vX-Y-Z`, the release
version with dashes, e.g. `0.1.6` → `v0-1-6`; plural `gcpstoragedefaultobjectaccesscontrols`), pulling the chart from
`oci://ghcr.io/krateo-blueprints/charts/gcp-storage-defaultobjectaccesscontrol` at that version.

### Create a Composition

```yaml
apiVersion: composition.krateo.io/vX-Y-Z   # VERSION with dashes, e.g. v0-1-6
kind: GcpStorageDefaultobjectaccesscontrol
metadata:
  name: my-defaultobjectaccesscontrol
  namespace: gcp-storage-system
spec:
  projectId: my-gcp-project
  # ... StorageDefaultObjectAccessControl spec fields (see values.schema.json)
```

### Check status

```sh
kubectl get gcpstoragedefaultobjectaccesscontrols.composition.krateo.io -n gcp-storage-system
kubectl get storagedefaultobjectaccesscontrols.storage.cnrm.cloud.google.com -A
```
